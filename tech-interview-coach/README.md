# Tech Interview Coach

根据目标岗位和技术栈，结合简历与常见核心面试题，逐题发现知识缺口、讲清原理，并练习面试表达。

每题按“提问 → 回答与追问 → 客观评价 → 参考回答与讲解 → 答疑与掌握验证”进行。评价说明掌握程度和与岗位要求的差距。你可以深入提问，也可以随时跳到下一题。

## 适合谁

- 正在准备技术岗位面试，希望系统检查基础、原理、实战和技术取舍的求职者。
- 简历写了项目，但需要练习说明本人贡献、设计理由、故障处理和验证效果的人。
- 希望根据职位要求复习薄弱点、持续记录进展的学习者。

技术栈、岗位层级和对话语言由使用者决定。可以用于后端、前端、数据或运维等技术方向，也可以在没有简历的情况下提供技术背景开始练习。主要使用方式是逐题学习与训练。

## 安装与开始

将完整的 `tech-interview-coach/` 文件夹通过宿主工具的技能安装入口启用，或放入该工具支持的 skill 目录。保留 `SKILL.md`、`references/` 和默认的 `data-location.json`，参考文件会按当前阶段读取。

宿主 AI 需要能读取技能文件。保存资料和跨会话恢复还需要文件写入能力及可写的数据目录；网络搜索用于研究高频主题和核实技术事实。宿主不能读取简历附件时，可以直接提供技术背景文字。具体安装目录和调用语法由宿主工具决定。

支持 `$skill-name` 调用的工具可以这样开始：

```text
$tech-interview-coach

我准备面试 Python 后端开发岗位。
技术栈是 Python、FastAPI、PostgreSQL 和 Redis。
优先检查数据库与接口设计，目标是能解释原理并独立处理常见故障。
我会提供项目经历，请先确认我的练习目标，再一次问一道题。
```

也可以不提供简历：

```text
使用 tech-interview-coach 开始模拟面试。
目标是前端开发岗位，技术栈是 TypeScript、React 和浏览器基础。
请先根据岗位要求建议需要掌握的深度，再检查我的薄弱点。
```

如果工具不支持技能名调用，可明确要求它读取并执行该文件夹中的 `SKILL.md`。

首次开始时，AI 会确认目标岗位与经验层级、优先技术栈、每项技术栈的练习方面和目标深度。可以提供目标职位描述，作为岗位差距评价的依据；也可以让 AI 建议目标。以后会复用已保存的设置。

## 怎样练习

1. **选题**：根据技术栈和岗位要求建立核心主题覆盖，利用可用网络工具研究常见重要题目，结合简历和薄弱点选题。简历未写出的岗位核心知识也会考察。
2. **作答与追问**：每次只有一道主要问题，回答后针对具体疑点连续追问。偏题时先拉回题目重答；答题阶段不提前给答案。
3. **客观评价**：依据有效回答判断“未掌握、部分掌握、基本掌握、熟练掌握”；证据不足的能力标为“未验证”。说明实际答到的内容、错误、遗漏，以及本主题与岗位要求的差距。
4. **讲解与答疑**：给出可口述的参考回答、回答组织思路和关键细节，继续解答你的疑问。
5. **掌握验证**：用不同情境的简短变式题检验能否独立运用。结果单独记录，不回改讲解前的面试表现。
6. **进入下一题**：验证通过后暂停，等你说“继续”或“下一题”。也可在当前题任一阶段明确说“下一题”或“换一题”，立即跳过。

指定某个方面会提高其选题优先级。默认仍覆盖该技术栈的岗位核心知识；希望只练某个范围时，请明确说明。

## 常用指令

| 你说的话 | 行为 |
| --- | --- |
| 下一题 / 换一题 | 立即结束当前题，保存已有记录并出新题；跳过本身不代表未掌握 |
| 继续 | 当前题未完成时继续本题；验证通过并等待下一题时进入新题 |
| 面试进度 | 查看当前阶段和已有记录 |
| 薄弱点 | 查看已发现的知识缺口和岗位差距 |
| 复习模式 | 优先练习尚未掌握的重要主题 |
| 改问某个技术栈 / 更深入 / 先练基础 | 更新练习设置，从下一道主要问题生效 |
| 补充项目经历 / 提供新版简历 | 默认补充原资料；明确更正或删除时才修改旧内容 |
| 把数据目录改到指定位置 | 更新定位记录并迁移已有资料与进度 |

## 资料保存与恢复

Skill 会保存技术背景、练习目标、主题覆盖、面试评价和掌握验证结果，供后续会话恢复当前题目并复习薄弱点。

整份简历、姓名、联系方式和其他个人识别信息不另存。背景用技术摘要；项目技术细节保留脱敏后的原文，便于深入追问。公司、客户和项目使用稳定代称，例如“公司 A”“项目 A”，不保存原名与代称的对照表。这里描述的是 skill 主动写入的文件；上传附件和对话的留存由宿主工具管理。

数据位置依次考虑：本次用户指定位置、先前记录的用户位置、适用 `AGENTS.md` 中的配置、其他有效记录、默认目录。默认是 skill 文件夹同级的 `data/`。最终位置记录在 `data-location.json`，后续直接复用；改变目录时按规则更新。

也可以在适用的 `AGENTS.md` 中写明：

```markdown
tech-interview-coach 的面试数据保存到 ./interview-data/。
```

该相对路径按 `AGENTS.md` 所在目录解析。用户直接指定的相对路径按当前工作目录解析。

```text
选定的数据目录/
├── interview-state.json   # 当前题目、问答摘要、评价、验证和历史
└── profile/
    ├── overview.md        # 岗位、技术栈、公司与项目代称索引
    ├── stacks/            # 练习目标、主题覆盖、掌握情况与岗位差距
    └── projects/          # 脱敏后的项目技术细节原文
```

同一数据目录维护一场进行中的面试。在新会话中使用同一位置即可继续；同时开展独立面试时使用不同数据目录。分发时打包完整 skill 文件夹和默认的相对定位记录，不携带使用者的面试数据或自定义定位配置。

## 能力边界

AI 的判断依据本次实际回答和可核实资料，不代表招聘结果。网络不可用时，仍可根据已有知识练习核心主题，但无法确认最新题目热度；技术细节不确定时应明确说明。

持久化效果取决于宿主的文件能力和访问权限。纯聊天环境不能保证自动保存和跨会话恢复。该 skill 没有独立的评分引擎或题库服务，行为由宿主 AI 按规则执行；具体平台的兼容性需要在相应环境中验证。
