# 简历与背景资料

仅在首次提供背景、新简历、项目细节补充或设置变化时读取本文件；日常进度更新使用 `progress.md`。

## 持久资料

```text
选定的数据目录/
└── profile/
    ├── overview.md       # 岗位、技术栈、公司与项目代称索引
    ├── stacks/           # 练习目标、主题覆盖与掌握情况
    └── projects/         # 每个项目脱敏后的技术细节原文
```

不保存整份简历或原路径。背景和技术栈用摘要；**项目技术描述保留原有措辞和细节**，只对公司、客户、项目原名及其他识别信息作必要替换，例如“公司 A”“项目 A”。姓名、联系方式、学校、地点、精确时间、账号、简历中的个人链接及可识别个人或组织的指标不落地；不保存原名、原名片段或掩码对照表。多个项目可引用同一公司代称，更新时沿用已有代称；对应不明时询问用户。

技术资料标明 `[简历技术摘要]`、`[简历项目技术原文·脱敏]`、`[用户补充]` 或 `[待核实推测]`。项目追问中用户补充的技术细节也可脱敏后保留原文。若发现旧版 skill 保存的简历副本或识别信息，先核对来源，提取允许保留的技术内容后只清理明确由本 skill 生成的副本和对应记录。

## 开场与更新

首次使用时，临时分析用户提供的简历；没有简历也可直接描述技术背景。展示提取出的技术栈和项目摘要以便纠正，然后确认目标岗位及经验层级、优先技术栈，以及**每项入选技术栈**想练的方面、目标深度和自评程度。用户提供职位描述时，将其作为岗位要求依据；没有明确岗位时以用户的学习目标为依据，不虚构岗位差距。深度可选 `基础`（概念用法）、`原理`（机制边界）、`实战`（实现排障取舍）、`深入`（源码或复杂架构）。可结合岗位建议目标，用户说“你定”时将建议记为暂定。再次启动只询问缺失或变化的设置。

用户提供新版简历或新经历时，默认**补充**现有技术栈和项目资料；没有再次出现的旧内容仍保留。用户明确更正、删除某项内容时才修改对应记录，出现冲突但意图不明时先询问。保留练习偏好和面试历史，受更正影响的掌握结论标为待验证。更新后简要说明变化，不保存新版简历。用户调整练习方向或深度，从下一道题起使用；若同时要求“下一题”，立即按跳题规则切换。
